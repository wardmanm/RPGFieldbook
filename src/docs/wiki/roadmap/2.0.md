# 2.0

The 2.0 refactor is not specified yet. This page is its starting point: the invariants any rework has
to keep unless they are discussed first, the structure the ledger already records as awkward, and
links to the 2.0 specs once they exist. The goals are Mike's to set.

## What 2.0 must carry

- **One shipped file, offline, no runtime dependencies.** It opens from `file://` and uses no
  modules. → [Build & source split](../architecture/build-and-source-split.md), [Overview](../overview.md)
- **Offline-first storage that fails loudly.** localStorage holds characters, settings and the
  library; IndexedDB, with every call timed out, holds the rules cache; a write that doesn't land says
  so. → [Storage](../architecture/storage.md)
- **Every existing save still loads.** `migrate()` preserves every field and then normalizes. New
  fields are optional and get a `blankChar()` default. → [Character model](../architecture/character-model.md)
- **Systems vs additive supplements, and per-system `dataVersion`.** → [Rules packs](../architecture/rules-packs.md)
- **Provenance and clean revert.** Removing a source (`race:`, `bg:`, `class:`) takes back its
  features, skills, equipment and gold. → [Grants & provenance](../architecture/grants-and-provenance.md)
- **Effects are numeric-only.** Advantage, resistance and senses stay prose. → [Computed stats & effects](../architecture/computed-stats-and-effects.md)
- **Armor drives AC**: `itemArmor()` and `armorAC()`, with `ac` effects stacked on top. → [Armor & AC](../features/armor-and-ac.md)
- **Spells sync into Attacks & Weapons** through `syncSpellAttack()`. An explicit "not an attack"
  sticks. → [Attacks & damage](../features/attacks-and-damage.md)
- **Tables are data, rendered from `cols`,** and are linked from prose by `[Table: Exact Name]`.
  → [Rules & tables](../features/rules-and-tables.md)
- **Escape first, then markdown on top of `highlight()`.** That order is the security argument.
  → [Rich text](../architecture/rich-text.md)
- **`notes` and `secNotes` are different things.** → [Story & notes](../features/story-and-notes.md)
- **A sheet holds copies, not definitions.** The rules-update tool never deletes, never touches the
  player's own numbers, and never updates without a backup. → [Rules-update tool](../features/rules-update-tool.md)

## Structural pain the ledger records

- **Fragments are positional slices.** They were cut at the original file's banner comments, not by
  concern, and their order is load-bearing (top-level TDZ). That is why `APP_VERSION` lives in
  `30-version.js`, and why `blankChar()`, which runs at top level in `00-constants.js`, cannot
  reference it. → ledger L370, L702
- **`50-classrace.js` holds more than its name says**: `renderClassRace()` and the shared grant
  machinery (`applyEquipGrants()`, `revertEquipmentGrants()`, `grantFeatDef()`,
  `addFeatureFromDef()`). Renaming it "rules-lookup" was rejected as even less accurate. → ledger L1262
- **`71-char-io.js` has no clean seam.** It holds cache hydration, `migrate()` and
  export/print/import. It was taken for size and flagged as the weak cut. → ledger L2592
- **Grants are keyed by source, not by level**, so a level-down cannot revert what that level gave.
  → ledger L2571
- **Choices leave no replay record.** ASI targets, skill picks, subclass, background feat and the
  ancestry ability spread survive only as their baked results. So an origin can never be re-applied
  wholesale, and the update tool has to work entry by entry. → ledger L702
- **Rules `_id` is positional.** `reindexRules()` reassigns it on every boot and import, so a copy
  finds its definition through a `src` stamp (pack, name, fingerprints) instead. → ledger L702
- **Form saves rebuild the record from the form.** One form at a time, the item, feature, attack and
  spell forms each dropped fields they don't display (`origin`, `src`, `itemId`/`spellId`). Each now
  carries them across by hand. → ledger L1659, L2381, L2742, L2863
- **`wire()` binds the whole UI in one pass with no try/catch.** A single missing id stops every
  listener after it, leaving a sheet that renders and is inert. Five bindings go through a guarded
  `on(id, ev, fn)`, 37 are still bare `getElementById(…).addEventListener`, and a `rules-data.js` guard
  checks that every id exists. → ledger L1666
- **Flow state in module globals.** `_equipQueue` outlived a dismissed window and fired after the next
  level-up, and it is now passed through instead. `_activeChoices` remains a global, and the single
  modal means stacked prompts can race. → ledger L3548, L3649, L2571
- **Pure logic is split from DOM code by hand**, one function at a time, so that it can be tested.
  `72-char-update.js` was re-cut to make "no DOM" true again, and `updBannerHTML()` was pulled out of
  `openChangelog()`. → ledger L2592, L1779

## Open questions

- Does 2.0 keep "one file, no build step to run it" as-is, or only "one file for players"? The second
  would free the source layout from positional slicing. See ADR-001.
- Should grants and choices become a recorded, replayable history (per level, per pick)? That would
  unlock level-down revert and wholesale origin updates, at the cost of a save-format migration.
- Which of the [known issues](known-issues.md) are in scope, and which stay deliberate?
