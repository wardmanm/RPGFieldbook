# 1.9.1

The fix release after 1.9.0. This page is its integration plan: what each issue touches and the
order they are built in. Drafted 2026-11-05 from three read-only passes over the 54 open 1.9.x issues
and the code; **scoped with Mike the same day** (below). No code is written. Each item still gets its
design when its wave starts (see "How a wave runs"). Every 1.9.x issue stays on the v1.9.0
milestone (Mike); the `1.9.1` and `1.9.2` labels say which release.

**See also:** [1.9.0's roadmap](../../archive/1.9.0/roadmap-1.9.0.md) (the wave method this copies),
[Known issues](known-issues.md), [2.0](2.0.md), [WORKTREES](../../WORKTREES.md),
[RELEASING](../../RELEASING.md)

- **Most P1s are small** (S or M) and sit in a few hot files: `90-boot.js`, `71-char-io.js`,
  `50-classrace.js`, `54-background.js`, `58-choices.js`, `41-chips.js`, `80-modal-forms.js`,
  `10-compute.js`, and the test file `src/tests/sheet.js`, which nearly every app fix extends.

  carried over from 1.9.0's reviews and pre-release. They are L-sized together and touch almost
  every fragment.
- **One item is not code:** #140 deletes the copyrighted assets of the v1.3.0–v1.7.2 releases. It is
  Mike's call alone, never done unprompted.

## The waves

Each wave is a set of worktrees run in parallel and merged one branch at a time, in the order given,
then one build and one QA pass on `main` ([WORKTREES](../../WORKTREES.md)). Worktrees in one wave
share some files, but never the same function; the merge order says who rebases.

| Wave | Worktrees (merge order) | Why here |
|---|---|---|
| **1** | Boot & storage · Grants redraw · Ammo undo · Glossary editor · Vitals & HP · Armour & attack numbers · Web fonts | The P1s with no dependency. Boot & storage merges first because Vitals & HP shares `90-boot.js` and `71-char-io.js` (other functions) |
| **2** | Bio chips · Skin & settings saves · ASI · Initiative | Skin & settings saves needs Boot & storage merged (`90-boot.js`, `71-char-io.js`). Bio chips and Skin share `41-chips.js` (other functions): Bio chips merges first |
| **3** | Backgrounds & Humblewood · Class training · Old release assets (#140) | Both code rows wait on wave 2: #160 on Bio chips' `applyBackground()`, #137 on ASI's `addClass()`. Each changes data; Class training regenerates the private packs, so one branch at a time touches them. #140 is no code: any time before the cut, on Mike's go-ahead |
| **Cut 1.9.1** | | The pre-release and the release (`/release 1.9.1`) |
| **4 (1.9.2)** | Layout and polish (#111 first) · the small, independent P2s | Polish against final layouts |
| **5 (1.9.2)** | #145 · #146 · #147 + #148 + #151 (one worktree: two print fixes) · #149 · #150 → #152 | The big groups, last; #152's docs pass goes after everything it describes |

## How a wave runs

As in [1.9.0](../../archive/1.9.0/roadmap-1.9.0.md#how-a-wave-runs): before a wave starts, its design
calls (the table's last column) are settled with Mike, as a short in-chat design for an S item or a
spec for an M or L one; then a plan, a worktree per row, tests first, `./src/tests/run.sh` green,
screenshots for anything visible, the wiki, ledger and `UNRELEASED.md` bullet in the branch; merge
one branch at a time; one QA pass on `main`. The release stays Mike's to cut (`/release`).

## Risks

- **`src/tests/sheet.js` conflicts.** Nearly every app fix adds tests there. Each branch adds its
  checks in a new block at the file's end, so merges are additions, not edits.
- **Bio chips is the wave-2 hub.** It edits five shared fragments; nothing else on
  `54-background.js`, `52-race.js` or `41-chips.js`'s chooser runs beside it.
- **Private data moves twice:** #160 (Humblewood) and #137 (all three converter packs). Each needs a
  private data release after its merge; they go one at a time.
