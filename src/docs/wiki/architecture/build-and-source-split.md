# Build & source split

Fieldbook is edited as 43 fragments under `src/` and shipped as one self-contained file,
`dist/fieldbook.html`. `scripts/build-html.js` splices the fragments into a page shell in the order
`src/manifest.json` gives, byte for byte, with no bundler and no module system: the result has to
open from `file://` on any device with no server. [ADR-001](../../ADR-001-source-split.md) is the
decision record; this page is how it works now and what a refactor must not break.

**Code:** `build()`, `validateOrder()`, `readFragment()`, `locate()`, `mayOverwrite()` in
`scripts/build-html.js`; the per-fragment and whole-file `node --check` steps in `build.sh` ·
**Data:** `src/manifest.json`, `src/fieldbook.template.html`, `.gitattributes`, `.editorconfig` ·
**Tests:** `char-update.js` (the concatenation evaluates with no TDZ error), `rules-data.js` (the
harness splice agrees with `dist/`), `docs.js` (fragment counts, one panel per html fragment) ·
**See also:** [Building & CI](../process/building-and-ci.md), [Testing](../process/testing.md),
[Character model](character-model.md), [Rich text](rich-text.md)

## How it works

**The shell.** `src/fieldbook.template.html` holds everything in the page that is not a tab panel:
the top bar, tab bar, ToC flyout, `<div class="page">`, the home screen, the generic modal and the
toast. It carries three markers, each a real comment in the context it sits in, so the template
stays valid on its own:

| Marker | Where | Filled with |
|---|---|---|
| `/*@@CSS@@*/` | inside the single `<style>` | `manifest.css`, 8 fragments |
| `<!--@@HTML@@-->` | inside `<div class="page">` | `manifest.html`, 7 fragments, one tab panel each |
| `//@@JS@@` | inside the single `<script>` | `manifest.js`, 28 fragments |

**The manifest is the order.** Not the filename prefixes, not a glob. `validateOrder()` runs over
each of `src/css`, `src/js` and `src/html` and dies on drift in both directions — listed but missing,
or present but unlisted — and on duplicates, symlinks, non-regular files, wrong extensions and
entries outside the directory.

**Each fragment is read as bytes.** `readFragment()` refuses an empty file, a UTF-8 BOM and any CR
byte, and warns and appends a newline when the last byte is not `\n`. Everything is `Buffer`-based,
so no decoding step can alter the output.

**Concatenation has no separator, for every kind.** Each fragment ends in exactly one `\n`; the
html panels also carry the blank line that used to follow them in the original file. The JS blob
must end in exactly `boot();\n` — a stray blank line at the end of `90-boot.js` fails the build, on
purpose.

**One splice pass.** `locate()` finds each marker exactly once in the original template; the
indices are computed up front and the blobs spliced in one pass. A marker is removed together with
its trailing newline, which is what keeps the output byte-exact. Sequential `String.replace` calls
were avoided because they are order-dependent (a CSS blob containing the JS marker would eat the JS
insertion) and would honour `$&`-style patterns inside the replacement.

**Writing, and the clobber guard.** An identical result is not rewritten, which keeps the mtime
and `git status` quiet. Otherwise `mayOverwrite()` allows the write only when the file on disk is
this builder's last output (its sha256 matches `dist/.buildstamp`) or the committed artifact
(`git show HEAD:dist/fieldbook.html`). Anything else is taken to be a hand edit: the build refuses
and says to port the change into `src/`, or to discard it with `--force`. The write truncates in
place rather than write-temp-then-rename, so the file keeps its mode.

**`--check`** builds in memory, writes nothing, and exits 1 if `dist/fieldbook.html` differs. It
is the gate in CI (except on a src-only PR, which CI builds instead) and in the pre-push hook. It is
deliberately **not** in `build.sh`, whose job is to fix staleness, not report it. Staleness is
decided by content, never mtime.

**After the build, `build.sh` checks syntax twice:** `node --check` on every manifest JS fragment on
its own, so an error names a fragment and a line in it rather than a line in the ~7,200-line
concatenation, then on the `<script>` extracted from the built file.

**Fragment names** are `NN-name.ext`, with multi-word names hyphenated. The prefix is a reading
aid. Deleting a fragment does not renumber the others, and two JS fragments share `87-`
(`87-combat.js`, `87-notes.js`). JS fragments are positional slices of the original single file, cut
at its own banner comments, so their boundaries follow the old file's layout rather than concepts.
Two are special:

- `30-version.js` holds `APP_VERSION`, `CHANGELOG` and `DATA_VERSIONS`. `dev.sh`, `release.yml`,
  `release.js`, `bundle-rules.js` and the `docs` and `char-update` suites all name it, so do not
  split or rename it.
- `05-icons.js` is generated by `scripts/fetch-icons.js` from `src/icons/icons.json`. Edit the map,
  not the fragment. See [Theming & icons](../ui/theming-and-icons.md).

## Rules that must hold

- **One shared global scope.** No `import`/`export`, no `type="module"`, no `<script src>`, no
  IIFE around a fragment, no per-fragment `"use strict"` (the one at the top of `00-constants.js`
  covers the whole script). `file://` gives the page an opaque origin that blocks ES modules and
  `fetch`, and several `<script src>` files are fragile on mobile.
- **Top-level order is load order.** Function declarations hoist, top-level `const`/`let` do not.
  `00-constants.js` runs `let character=blankChar()` at load, so `blankChar()` may read only what is
  defined above it. That is why `COMBAT_DEFAULTS` lives in `00-constants.js` rather than
  `87-combat.js`, and why a new character's `appVersion` is `""` until `newCharacter()` stamps it:
  `APP_VERSION` is in `30-version.js`, later in the file. A reference the other way is a
  `ReferenceError` before any UI exists: a white screen.
- **Cut, don't reorder.** Moving code between fragments is safe only as a contiguous slice in the
  original order. That is why byte-identity of `dist/` is a complete proof for a pure split:
  reordering is the only thing that can break a top-level TDZ, and slicing cannot reorder.
- **`boot();` is the last line of the JS.** Machine-checked by the builder.
- **Every JS fragment parses on its own.** No statement may span a fragment boundary, or the
  per-fragment `node --check` fails.
- **Byte hygiene.** LF only, no BOM, exactly one final newline in every fragment, the template and
  the manifest. `.gitattributes` pins `eol=lf` for every file, because a CRLF checkout would
  silently add ~3,100 bytes to the shipped app; `.editorconfig` asks editors for the same. A BOM
  before `"use strict"` breaks the directive prologue and silently turns strict mode off, which
  `node --check` would not notice. Invisible characters belong in source as escapes, never as raw
  bytes (see [Rich text](rich-text.md)).
- **Adding or removing a fragment means editing the manifest,** and `git add`ing the file: the
  pre-commit hook's `check_manifest_tracked` catches a listed fragment nobody staged, which would
  build here and break on a clean checkout.
- **Every html fragment holds exactly one `<section class="tabpanel">`** (asserted in `docs.js`).
- **`dist/fieldbook.html` is never hand-edited.** It is tracked because it is the release artifact,
  the file the update badge sends players to, and the clobber guard's reference.

## Traps

- **A glob would ship scratch files.** This repo accumulates `*.OLD.js` copies; a sorted glob
  would concatenate one ahead of the real fragment and still pass `node --check`. Hence the
  manifest, and the two-way drift check.
- **CI enumerates the source directories by name.** The manifest-parity step and the byte-hygiene
  loop in `ci.yml` list `src/js`, `src/css` and `src/html` literally. When `src/html/` was added,
  both had to learn it, or an unlisted panel would ship nothing while CI stayed green. A fourth
  source directory needs the same edits.
- **The test harness re-implements the splice** (`harness.loadHTML`) rather than calling
  `build-html.js`, which builds and exits at require time. A test using the builder's own splice
  could never catch the builder splicing wrongly. One assertion in `rules-data.js` pins the two
  together against `dist/fieldbook.html`, so a stale artifact fails it: rebuild before believing
  that failure. `harness.loadApp` joins JS on `\n` where the builder uses no separator. That is
  harmless for evaluation, but it means the harness does not reproduce the artifact byte for byte.
- **`build.sh` was once zsh-only.** An apostrophe inside a `<<'NODE'` heredoc nested in a command
  substitution opened a quote bash never closed, so `./build.sh` validated and then died at the
  changelog step. The block moved to `scripts/gen-changelog.js`, and CI now runs `bash -n build.sh`
  so the break cannot come back silently.
- **Weak seam:** `71-char-io.js` was cut from `70-persistence.js` for size. It carries the async
  rules-cache hydration, `migrate()`, export, print and import, which its name only half describes.

## Decisions

| Question | Decision | Rejected, and why |
|---|---|---|
| How to split the source | Plain fragments concatenated into one file | ES modules or several `<script src>` files: `file://` blocks modules and `fetch()`, and multi-file loading is fragile on mobile (ADR-001) |
| What decides fragment order | `src/manifest.json`, checked both ways | A sorted glob or the prefixes: a stray `*.OLD.js` would ship and still pass `node --check` (ADR-001) |
| Where fragment boundaries fall | Positional slices at the original banner comments | Concern-grouped files as ADR-001 first sketched: that is a reorder, and a reorder can break a top-level TDZ |
| The CSS marker | `/*@@CSS@@*/` | `<!--@@CSS@@-->`: an HTML comment inside `<style>` is not a CSS comment (ADR-001) |
| How staleness is detected | Content hash: `--check`, `.buildstamp`, HEAD | mtime: does not survive checkout or clone, so it gives false alarms and false all-clears (ADR-001) |
| Where the stale check runs | CI and the pre-push hook | Inside `build.sh`, whose job is to fix staleness (CLAUDE.md) |
| Whether `dist/fieldbook.html` is tracked | Tracked | Gitignored: it is the release artifact, the update badge's target and the clobber guard's reference (ADR-001) |
| How the tests assemble the markup | Re-implement the splice in the harness | Call `build-html.js`: it builds and exits at require time, and could never catch its own splice going wrong (ADR-001 part 2) |
| Renaming `72-charupdate.js` | `72-char-update.js`: every other multi-word fragment hyphenates, and its test is `char-update.js` (L1262) | — |
| Renaming `50-classrace.js` to `50-rules-lookup.js` | Keep `50-classrace.js` | The new name: the fragment also owns `renderClassRace()` and the grant machinery, so it described it less accurately (L1262) |
| Renumbering prefixes after `50-tables.html` was deleted | No | Renumbering: pure churn, since the manifest is the order (L2714) |

## Open

- ADR-001's "As built, part 2" still says JS fragments are joined with a newline, and still
  describes a Tables panel fragment with no banner comment. The builder uses no separator for any
  kind, and that fragment was folded into `40-rules.html` in #32.
- The template links Google Fonts (`fonts.googleapis.com`). This is the only third-party URL in the
  shipped file, and it predates the split. Offline, the font stacks in `00-tokens.css` fall back to
  Georgia/Times. Non-negotiable 1 forbids a new `<link href>` to a third-party URL, and no recorded
  decision covers this one. See [Known issues](../roadmap/known-issues.md).
