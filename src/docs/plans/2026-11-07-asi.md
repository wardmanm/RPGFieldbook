# ASI: every increase asked, none past 20 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fighting Style feats qualify and count as taken from the class's own style (#172). Every ASI
step starts blank, names its level and counts in Picks left. No increase passes 20 (30 for an Epic
Boon's), in level order on screen and at Done. A feat is offered once per window (#171; #146 S2-24 and
S2-26 ride along).

**Architecture:** Everything is in `58-choices.js`. Pure functions decide: the Fighting Style walk,
whether a step is set, what a step adds, and the level-order ledger. `commitAsiPick()` uses the same
ledger. One DOM function, `asiRefresh()`, applies the ledger to the open window. `wireAsiFeats()` runs
it on every change. CSS for the disabled states goes in `50-modal.css`.

**Tech Stack:** plain JS fragments concatenated into one file, CSS fragments, Node suites in `src/tests/`.

**Spec:** `src/docs/specs/2026-11-07-asi-design.md` (approved by Mike, 2026-11-07).

### Task 4: No increase past 20, in level order (#171)

**Files:**

**Interfaces:**
- Consumes: `asiReadStep()`, `asiStepDone()` (Task 3); `featPendingIncreases()`, `contributions()`.
- Produces:
  - `asiScore(k) -> number`: `num(character.abilities[k])` plus `sumFx("ability."+k, …)` over the
    `kind==="feature"` entries of `contributions()`.
  - `asiScores() -> {str,dex,con,int,wis,cha}`.
  - `asiStepIncreases(sel, feat) -> {route:"asi"|"feat"|"none", complete:boolean,
    incs:Array<{k, n, cap, fixed, i}>}`:
    - an ASI: mode "2" gives `{k:a, n:2, cap:20}`; mode "1" gives `a` and `b`, each `n:1`.
      `complete` is `asiStepDone()`;
    - a feat: each fixed increase of `featPendingIncreases(feat)` as `fixed:true, cap:20`, and each
      answered choose group as `{k:plus[i], n:amount, cap:max||20, i}`;
    - no pick: `"none"`.
  - `asiLedger(base, steps) -> Array<{before, adds, invalid}>`. It walks `steps` in order with
    running scores:
    - an ASI that isn't complete adds nothing, and `invalid` lists those of its increases that don't
      fit;
    - a complete ASI adds all of its increases if they all fit. Otherwise it adds nothing, and the
      ones that don't fit go in `invalid`;
    - a feat adds each increase that fits. A chosen one that doesn't fit goes in `invalid`; a fixed
      one is skipped.
    "Fits" is `before[k] + addedSoFar[k] + n <= cap`.
  - `commitAsiPick(sel, origin, pending)`: computes
    `asiLedger(asiScores(), [asiStepIncreases(sel, feat)])[0]`. An ASI writes its feature only when
    it is complete with `invalid` empty. A feat is granted, and its feature gets exactly `adds` as
    effects.
  - `asiPanelHTML(ch, ci, pick, before=asiScores())`: a fixed increase with no room reads "+1
    Strength (already 20: no increase)", with that cap's number.
