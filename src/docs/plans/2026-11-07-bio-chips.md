# Bio chips Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tool proficiencies become Bio chips that arrive and leave with their background, with a
choice asked when the background is added and a placeholder chip otherwise. The chips and their Add
window get room, and that window takes several picks at once. Removing or swapping a species,
background or class takes back the speed, size, spellcasting ability and text it seeded, never the
player's own values, and a Speed window gives the player a Base speed of their own.

**Architecture:** Tools are a fifth chip list (`tools`) in `41-chips.js`, read through the existing
`chipList()`/`chipClean()`. A pure `toolParse()` turns a pack's wording into named tools and choices,
`grantTools()` stamps them with the background's sid, and a `tool` step in `runExtraChoices()` names
the placeholders it made. Seeds are recorded in a new list, `character.seeds`, by three helpers in
`50-classrace.js` (`seedField()`, `unseedSource()`, `setPlayerField()`). Every seed site and every
remove path goes through them, and the Size and Speed windows write a `player` entry that both
helpers respect. The Speed window copies the AC window's shape in `80-modal-forms.js`.

**Tech Stack:** plain JS fragments concatenated into one file, CSS fragments, Node suites in `src/tests/`.

**Spec:** `src/docs/specs/2026-11-07-bio-chips-design.md` (approved by Mike, 2026-11-07). Decision
numbers below are the spec's.

## Review Focus

1. **A hand-edited file with junk in the new lists** (`tools:"x"`, `tools:[null,{name:5},{name:"Lute",ask:7}]`,
   `seeds:[{sid:"race:Elf",field:"hp",value:1},{field:"speed",value:{}}]`): the sheet loads, the card
   renders, and a second `migrate()` changes nothing. Tests in Task 1 (tools) and Task 5 (seeds).
2. **The same background or species applied again** (Change to the one already there): no doubled
   chips or placeholders, one seed entry per sid and field. Tests in Task 1 and Task 5.
3. **A placeholder named to a tool the player already owns, then the background removed**: the
   player's own chip stays, the background's chips go, and nothing is named twice. Test in Task 2.
4. **A source that carries none of the seedable fields** (Humblewood species with no `size`, a custom
   ancestry, a class with no `spellcasting`): no entry is written for a field it doesn't carry,
   nothing stores `undefined` or `NaN`, and removing it touches nothing. Test in Task 5.
5. **A typed Base speed of 0** (a creature that can't walk): taken, kept through a swap, not read as
   empty by `seedField()`. Test in Task 6.
